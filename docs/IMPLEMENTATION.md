# 초기 구현 및 실행 기록

기준: 2026-10-22. 사용자 승인 범위는 이 저장소의 구현·로컬 시뮬 시험·결과 기록이다. 기존 관제·USD 원본·Isaac 설치본의 소스는 수정하지 않았다. 설치·실물 실행·Git 커밋/push는 수행하지 않았다.

## 구현한 범위

- 200×150cm 공간, 75cm 작업 구역/통로, A/B/인계 중앙 접합부 목표 43/43/42cm를 설정 파일에 반영했다.
- OMX 중심축 벽 거리 14cm·설치면 높이 11cm, 카메라 높이 80cm·벽 거리 12cm를 반영했다. 카메라 좌우 오프셋·화각과 선반 크기·칸막이 두께/높이는 가정이다.
- 변환된 공식 USD를 참조하여 **단일 Pinky의 바퀴 구동**, 뒤쪽 바닥 바구니, 정적 OMX 3대를 구성했다. 이동 중 로봇 위치를 강제로 옮기지 않는다.
- 바구니는 차체와 같은 강체에 포함한 충돌 형상이다. 후속 사용자 결정에 따라 기본 모델은 바닥에서 5mm 띄운 표현을 사용하고 바구니-바닥 접촉만 제외한다. 벽·물건·다른 로봇 충돌과 평면 외곽은 유지한다. 질량 50g·간격 5mm·관성 근사는 실측값이 아니다. 테이프 탄성이나 상대 미끄러짐 모델은 없다.
- ROS 명령 수신 → 바퀴 속도 목표 → PhysX 이동, 정답 자세·TF·관절·시각 송수신을 구현했다. 현재 두 노드는 같은 프로세스 안에서 RMW를 사용한다.
- 방향별 통로와 회차의 기하 검사, 원자적 구역 예약·FIFO·통신 불명 시 점유 보존·확인된 바구니 이탈 후 해제 로직을 작성했다.
- 최종 바구니 관측을 받을 도킹 판정 모듈을 작성했다. 영상 소실·오래된 관측·카메라 기준 변경 때 정차 허가를 막는다. 위치/방향/정지/유지시간 기준은 호출자가 모두 지정해야 한다. 검출기나 후진 보정 제어기는 아직 없다.
- `config/baseline/`에 사용자 제공 압축파일의 지도와 Pinky2 저장 Nav2 설정을 원본 그대로 복사하고 해시를 검증했다. 바구니 footprint 또는 후진 런타임 설정을 그 파일에 임의로 적용하지 않았다.

마지막 행은 시뮬 내부 값이다. 정밀주차 정확도나 실물 반복성 주장에 사용하지 않는다.

**이전 접촉 모델의 판단:** 기본 로봇은 전후진·회전 가능하다. 바구니를 추가한 바닥 접촉 모델에서 큰 회전 부족이 발생했다. 게인만 바꿔 해결되지 않았고 바구니 제거 비교에서 회복됐다. 이후 아래 9조건 시험에서 접촉·마찰 민감도를 확인했다. 실제 로봇이 동일하게 회전하지 못한다거나, 원인이 마찰 하나라고 확정하지 않는다. 현재 기본값은 후속 사용자 결정의 바닥 접촉 제외 모델이며 smoke-005 결과를 따른다.

telemetry의 `dof_efforts`는 API가 돌려준 명령 feedforward effort다. 실제 모터 토크·접촉력 측정값으로 읽지 않는다. 구동/접촉 원인 분해에는 별도 측정이 필요하다.

### 바구니 포함 회전 후속 시험

[9조건 비교 기록](BASKET_ROTATION.md)을 추가했다. `basket-sweep-002`는 완료됐으며 명목 180° 명령에서 바구니 없는 모델 177.58°, 질량·관성만 추가한 모델 178.04°, 기본 바구니 모델 2.31°, 바닥 접촉을 유지하고 마찰을 0으로 한 모델 176.76°였다. 가정값의 비교이며 실제 마찰을 선택한 것이 아니다.

접촉 보고 API로 바닥 지지력 분포도 기록했다. 기본 바구니 모델에서는 차체+바구니에 약 3.62N, 캐스터에 약 0.24N이 걸려, 바구니가 로봇 하중 일부를 받는 모델임을 시사한다. 기본 조건을 다른 위치에 둔 반복 모델과의 짧은 회전 응답 차이도 남아 있다. 접촉 형상·높이·수치 설정을 검토해야 하며 물리 보정 완료로 처리하지 않는다.

바구니 포함 보수적 회전 범위는 고정 원점 기준 지름 약 47.91cm다. 75cm 공용통로의 차로 하나를 넘으므로 회전과 겹치는 차로의 점유도 예약해야 한다. 실제 배치 평면 검사와 비교용 물리 시험장의 결과를 구분한다.

## ROS 시험 범위와 환경 제한

- smoke-002와 smoke-003 모두 cmd_vel 600회 수신, 정답 odom·clock·joint_states·TF 각각 600회 수신, watchdog 만료 반환값 확인.
- `rmw_fastrtps_cpp`, domain 83, localhost. 실제 Ubuntu 노트북과의 통신이나 Pinky 장비 연결은 하지 않았다.
- 설치본은 `6.1.0-rc.26+release.49347.2d230af4.gl`, GPU RTX 5090 / 드라이버 610.88.
- 번들에 nav2_common/nav2_msgs/nav2_simple_commander가 있지만 controller/planner/route 서버 패키지는 확인되지 않았다. WSL 조회는 미설치를 반환했다. 현재 **Nav2 서버 실행은 미검증**이다.
- 초기 캐시·ROS 로그 경로 쓰기 오류와 FastDDS SHM 전송 생성 오류가 기록됐다. 실제 RMW 루프백은 성공했다. 프로젝트 캐시, ROS_LOG_DIR, OmniGraph 캐시 재지정과 UDP 설정을 실행기에 추가했다. **ROS_LOG_DIR 추가 후 전체 ROS 실행은 아직 재검증하지 않았다.** `FASTDDS_BUILTIN_TRANSPORTS=UDPv4`만으로 해당 설치본의 SHM 경고가 제거되지는 않았다.
- 앱의 fast shutdown은 검사 실패에도 OS 종료 0을 반환할 수 있었다. 실행기는 `run.json`의 `passed_smoke`까지 확인하도록 수정했다. smoke-003은 OS exit 0이어도 실행기에서 실패로 처리했다.
- 런타임에는 별도 시간 제한을 두었다. 시험 산출물은 실행별 폴더에 보존한다.

## 도로·관제·도킹 로직 시험

현재 자동시험 **36개 통과**. [이전 26개 시험 출력](../outputs/unit-tests.txt), [도로 v3와 기본 대기줄 검사](ROUTE_VALIDATION.md).

- 반대 요청의 단일 허가, 원자적 예약, 충돌 요청 FIFO, 무관한 구역의 진행.
- 바구니 미이탈·오래된 관측·다른 식별자·통신 단절에서 점유 유지.
- 중복 명령, 대기 취소, 알 수 없는 자원, 동시에 들어온 8개 요청.
- 속도 한도, 수신 만료·시계 역행·NaN에서 정지 명령.
- 바구니 외곽을 빼면 놓치는 충돌, 벽/경계 침범, 접합부 목표 좌표.
- 도킹 관측 소실·기준 변경·시간 역행/만료·중복 프레임·정지 유지 조건.

[오프라인 기록](../outputs/offline-002/result.json)은 별도 프로그램의 합성 관측으로 예약 전이를 확인한 것이다. 실제 카메라·로봇 구역 이탈 판정이나 두 로봇 충돌 시험이 아니다.

초기 v2의 방향별 직선 차로 중심은 Y=-1.30/-0.95m였다. 초기 회차 중심 X=.30/1.70m에서는 후면 바구니 외곽이 공간 밖으로 약 3.2cm 넘어갔다. X=.38/1.62m로 안쪽 이동한 후보는 361개 표본에서 외곽 확장 0/1/2/3cm 검사 통과, 4cm에서 실패했다. 이는 이전 도로의 이산 기하 검사이며 현재 v3나 실물 여유의 근거가 아니다.

도로 v2에서 작업대별 진입/출차를 연속 기준 경로로 연결하고 모든 작업대 쌍 6개의 바구니 외곽을 검사했다. A/B 적재 위치 대기와 다른 로봇의 왕복도 검사했다. 두 대의 교대 인계는 시간 경로 모사로 완료됐으며 13.75초의 동시 경로 진행과 오래된 이탈 관측의 정지·점유 유지가 확인됐다. [결과](../outputs/routes-v2-002/result.json). 이는 Isaac 물리 추종이나 실기 검사와 구분한다. 내부 그래프 버전 2는 Nav2 Route Server 배포 파일이 아니다.

## 산출물과 재현

후속 v3에서는 차로 중심 간격 24cm(Y=-1.19/-0.95m)와 좌하단 두 대의 FIFO 기본 대기줄을 연결했다. 기본 대기→적재→교대 하역→복귀 모사는 191.05초에 완료했고, 이는 설정한 속도와 적재/하역 시간을 사용한 계산값이다. 작업대 간 6개 및 대기줄 관련 10개 경로, 36개 자동시험, 재생 화면 검사가 통과했다. [v3 결과](../outputs/routes-v3-001/result.json), [현재 도면과 전체 설명](ROUTE_VALIDATION.md).

## 다음 구현 지점

이미지 10장·영상 3개·원본 재생과 검증 근거를 [별도 보관](MEDIA.md)하여 이번 자료 준비를 마무리했다. 두 대 영상은 기준 자세의 Isaac 렌더이며, 바퀴 녹화는 단일 로봇의 기본 물리 시험이다.

1. 다음 세션의 관제 저장소에서 명시적인 시뮬 출처를 가진 이동 명령 1개의 요청·취소·결과 왕복을 연결한다. [인계 문서](MEDIA_HANDOFF.md)를 먼저 확인한다.
2. 도로 v3의 실제 Isaac 바퀴 추종·정지·충돌 여유와 임의 주문/복귀 순서의 교통 운영을 검증한다. 바구니 바닥 저항 제외 가정은 유지한다.
3. Linux/Nav2 환경, 센서 기반 odom/scan·TF/clock, pinky_map_new와 layout 정렬, 정밀 도킹과 실기 전이를 검증한다. 설치·실물 접속은 별도 승인 범위다.

새 현장 자료를 지금 다시 모으라는 요청은 하지 않는다. 현재 미측정 값은 가정으로 유지하고 추후 실물 전이 시험에서 비교한다.
