# 바구니 포함 회전 비교

> 후속 사용자 결정: 바구니가 살짝 떠 있고 바닥 저항이 거의 없는 것으로 단순화한다. 아래 결과는 이전 바닥 접촉 모델의 이력이다. 현재 기본 모델과 도로 개발 범위는 [도로·관제 인계 문서](ROAD_HANDOFF.md)를 따른다. 아래의 추가 마찰 실험을 선행 조건으로 요구하지 않는다.

2026-10-22. 기존 Isaac Sim에서 바퀴를 구동하여 9가지 모델을 비교했다. **현재 모델의 회전 부족은 바구니의 추가 질량만으로 설명되지 않으며, 바닥 접촉과 마찰에 크게 의존한다.** 실제 바구니의 마찰·변형·접합 높이를 보정한 결과는 아니다.

## 시험과 근거

- [실행 결과](../outputs/basket-sweep-002/run.json), [전체 궤적](../outputs/basket-sweep-002/trajectory.json), [실행기 결과](../outputs/basket-sweep-002-supervisor.json).
- [초기 장면 USD](../outputs/basket-sweep-002/bench.usda), [종료 후 렌더](../outputs/basket-sweep-002/overview.png), [실행 코드](../tools/basket_sweep.py).
- 시험장은 모델 간 간섭을 피하기 위한 3.8×3.6m 비교용 바닥이다. 실제 200×150cm 쇼핑 배치나 다중 로봇 교통 시험이 아니다.
- 동일한 로봇 자산·바퀴 구동·물리 시간 간격을 사용하고 모델들을 1m 간격으로 놓았다. 로봇 자세를 강제로 옮겨 회전을 만들지 않았다.
- 정착 1초 → 전진 0.1m/s 2초 → 정지 1초 → 후진 -0.1m/s 2초 → 정지 1초 → 회전 0.5rad/s 2초 → 정지 1초 → 회전 0.5rad/s 약 6.283초 → 정지 1초.
- 아래 회전량은 각 구간의 시작 자세 기준이다. 두 회전의 누적각이 아니다. 목표각을 관측해 멈추는 제어기가 아니라 **정해진 시간 동안 같은 바퀴 속도 목표를 주는 시험**이다.
- 첫 실행 `basket-sweep-001`은 접촉 보고 API 활성화 누락으로 중단됐다. 설정을 수정한 002가 완료됐으며 001은 회전 성능 자료에서 제외한다.

## 측정 결과

| 모델 조건 | 명목 57.30° 구간의 회전량 | 명목 180.00° 구간의 회전량 |
|---|---:|---:|
| 바구니 없음 | 56.45° | 177.58° |
| 기본: 50g, 바닥 접촉, 유효 마찰 0.425 | 11.55° | 2.31° |
| 50g 질량·관성만 추가, 바구니 충돌 꺼짐 | 56.56° | 178.04° |
| 50g, 바닥 접촉, 유효 마찰 0 | 56.15° | 176.76° |
| 50g, 바닥 접촉, 유효 마찰 0.05 | 50.21° | 157.70° |
| 질량만 5g으로 감소, 기본 접촉·마찰 | 7.68° | 4.16° |
| 바구니 형상을 1mm 올림 | 39.64° | 124.27° |
| 바구니 contact offset을 1mm로 지정 | 1.37° | 2.32° |
| 기본 조건 반복, 다른 시험 위치 | 1.50° | 2.02° |

바닥 재질 마찰은 0.6, 기본 바구니 재질은 0.25이며 평균 결합이어서 접촉 쌍의 유효 값이 0.425다. 마찰 0/0.05 비교에는 `min` 결합을 명시했다. 바구니 재질만 0으로 바꾸고 평균 결합을 유지하면 접촉 마찰이 0이 되지 않는다. [PhysX 공식 결합 규칙](https://nvidia-omniverse.github.io/PhysX/physx/latest/_api_build/structPxCombineMode.html).

**이 값들을 실제 바구니 마찰이나 주차 오차로 사용하지 않는다.** 기본 조건의 짧은 회전량도 위치가 다른 반복 모델에서 11.55°와 1.50°로 달랐다. 두 조건만으로 반복성 통계를 주장할 수 없으며, 접촉 상태와 수치 설정에 대한 민감도가 남아 있다. 형상 1mm 상승 시험도 마찰 0 시험처럼 회복되지는 않았다.

## 접촉력으로 확인한 점

180° 명령 구간의 시작 10프레임을 제외한 평균 수직 접촉력이다. Isaac의 접촉 보고를 물리 dt로 나눈 값이며 모터 토크가 아니다. 아래 차체 열에는 같은 강체에 붙인 바구니가 포함된다.

| 조건 | 차체+바구니 | 왼쪽 구동 바퀴 | 오른쪽 구동 바퀴 | 캐스터 |
|---|---:|---:|---:|---:|
| 바구니 없음 | 0N | 4.09N | 5.18N | 5.84N |
| 질량·관성만 추가 | 0N | 3.52N | 4.90N | 7.18N |
| 기본 바구니 | 3.62N | 6.30N | 5.43N | 0.24N |
| 바닥 접촉, 마찰 0 | 4.25N | 6.45N | 4.42N | 0.48N |

접촉을 켜면 차체+바구니 쪽으로 지지력이 이동하고 캐스터 지지력이 줄어든다. 바구니 추가 질량 50g의 중력 약 0.49N보다 큰 힘이다. **강체로 고정한 바구니가 로봇 하중 일부를 받는 모델로 동작한다는 해석을 지지한다.** 물건이 가벼워도 바닥 저항이 작다고 단정할 수 없는 이유다. 다만 이 근사 모델의 지지 상태가 실물과 같은지는 확인되지 않았다.

기본 모델에서 바퀴는 계속 회전하지만 차체 회전은 거의 진행하지 않는다. 마찰을 줄이거나 접촉을 끄면 회복되는 것은 현재 모델의 접촉 저항과 바퀴 미끄러짐이 주요 검토 대상임을 보여준다. 합격을 만들기 위해 기본 설정의 마찰을 낮추지는 않았다.

## 실제 배치에서 필요한 회전 공간

동역학 비교와 별도로 `config/layout.json`의 로봇·후면 바구니 외곽을 사용했다. 로봇 원점에서 가장 먼 모서리까지 약 23.95cm여서, 고정된 원점 주위 전체 회전의 보수적 원형 범위는 **지름 약 47.91cm**다. 원점과 실제 회전축의 일치, 추종·위치 추정·제동 오차는 포함하지 않는다.

- 75cm 통로 안에 이 범위를 배치할 수 있지만 두 차로로 나눈 한쪽 폭을 넘는다. 제자리 회전은 이웃 차로와 겹치는 자원을 함께 예약해야 한다.
- A/B/인계 정렬 후보 중심 `(0.3,-0.79)`, `(0.9,-0.79)`, `(1.6,-0.79)`m와 통로 중앙 `(0.9,-1.125)`m는 1° 간격 360개 자세에서 외곽·칸막이 검사상 충돌이 없었다.
- 칸막이 앞 `(0.6,-0.95)`m에서는 39개 자세가 충돌했다. 통로 어디에서나 회전 가능하다는 뜻이 아니다.
- 위 검사는 평면의 바닥 경계·칸막이만 포함한다. 다른 로봇·물건·카메라 시야·연속 궤적·동적 오차의 검증은 별도다. 도로망의 실행 허가를 확정하지 않는다.

## 다음 실험의 기준

1. 같은 중심 위치에서 초기 접촉 상태를 재설정한 반복 시험과 작은 높이·마찰 변화로 민감도를 확인한다. 현재 비교의 위치별 차이를 실물 반복 오차로 해석하지 않는다.
2. 회전 가능한 가정 모델에서는 자세 피드백으로 목표각까지 회전한 뒤 실제 배치에서 바구니가 지나가는 영역과 정지 상태를 검사한다. 회전 정체에는 시간 제한·정지 처리가 필요하다.
3. 외부 설치나 새 현장 수집을 지금 선행 조건으로 두지 않는다. 가정 범위의 성공과 추후 실물 전이 검증 결과를 분리하여 보관한다.

재현은 저장소 루트에서 새 출력 이름을 사용한다.

```powershell
python -B tools/launch_sim.py --basket-sweep --output outputs/basket-sweep-next --timeout 360
```

이 명령은 ROS를 연결하지 않는다. 정상 완료 표시는 `completed_experiment`이며 실물 정확도 합격 표시가 아니다. 실행 때 사용한 코드·주 자산 해시는 `run.json`에 보존된다. 원본 자산 의존 파일 18개의 해시는 기존 명세와 일치했다.
