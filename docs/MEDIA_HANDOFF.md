# 도로 v3 자료와 관제 통합 인계

기준일: 2026-10-22. 이 저장소의 이번 마무리 범위는 도로 v3의 이미지·영상·재생 원본·검증 근거 보관이다. 다음 개발은 `kernel-robot-repo-3`의 관제와 시뮬 이동 명령을 연결하는 단계다.

## 완료 범위와 자료 해석

- 전체 공간 200×150cm, 작업 구역/공용통로 각각 깊이 75cm. A/B/인계 폭 60/60/80cm.
- 바구니 127mm 면을 Pinky 후면에 밀착 고정. 평면 외곽에는 바구니를 포함하며, 시뮬에서는 바닥 저항을 제외한다. 5mm 간격은 표현용 가정이다.
- 위쪽 서향 차로 Y=-0.95m, 아래쪽 동향 차로 Y=-1.19m. 좌하단 기본 대기줄은 앞차 우선이며 뒤차가 독립적으로 빠져나갈 수 없다.
- 도로 내용 버전 3, 내부 그래프 형식 버전 2. 그래프는 Nav2 Route Server의 배포 형식이 아니다.
- 작업대 간 6개 경로, 기본 대기 관련 10개 경로, 두 대의 적재·교대 인계·복귀 기준 모사와 36개 자동시험을 통과했다.
- PNG와 두 대의 Isaac 영상은 계산된 자세를 보여주는 설명 자료다. 두 대의 전체 경로를 바퀴로 추종한 물리 시험 결과가 아니다.
- 별도의 단일 Pinky 영상은 실제 바퀴 속도 목표와 PhysX 이동을 기록한 시험이다. 실물 정확도, 센서 도킹, Nav2 주행 성공 근거로 확대하지 않는다.

자료 폴더의 `index.html`에서 이미지와 영상을 고르고, `README.md`에서 사용 가능한 설명을 확인한다. 파일별 해시와 출처는 `manifest.json`에 보관한다. 자료를 다시 만들 때는 새 날짜/버전 폴더를 만들고 이번 결과를 덮어쓰지 않는다.

## 이번에 고정한 예제와 남은 범위

예제는 1번이 선두에서 A로, 2번이 후열에서 B로 이동해 각각 적재한 뒤 인계 구역을 순서대로 사용한다. 1번은 기본 대기 선두, 2번은 후열로 복귀한다. 두 대의 적재 완료를 기다렸다가 동시에 인계를 요청하게 구성했다.

임의 주문에서 두 로봇 모두 A와 B를 방문하는 순서, 임의 복귀 순서의 대기줄 자리 배정, 중간 취소 후 대피와 재개, 장기 교착 해소는 추가 검증 대상이다. 표본 예제의 고정 슬롯 배정을 일반 관제 규칙으로 그대로 적용하지 않는다.

각 로봇 외곽 2cm 확장 검사는 가정한 선반·칸막이·바닥 경계와 기준 경로에 대한 결과다. 일부 구간의 추가 여유가 수 mm이므로 실제 추종·제동·센서 오차를 측정해야 한다. 양옆 선반과 고객 바구니, 팔이 움직이는 작업 영역은 모델에 완전히 들어있지 않다.

## 관제 저장소에서 확인한 현재 연결 지점

아래는 이번 인계 준비 중 읽은 실제 코드다. 관제 저장소는 수정하지 않았다.

- `robot_gateway/hardware/worker.py`: `mobile_factory`로 생성한 객체의 `execute(command, cancelled)`를 호출한다. hardware 모드 이외 명령은 거부한다.
- `robot_gateway/interfaces.py`: `MobileAdapter`에는 navigate/leave/stop Protocol이 있다. 실제 worker 진입점과 같지 않으므로 어댑터 계약을 먼저 정리한다.
- `robot_gateway/hardware/evidence.py`: 장비 관측 파일은 명령 식별자·실행 식별자·관측 신선도를 확인하고 vision/feedback/operator 출처만 받는다.
- `server/api.py`: 현재 명시된 모드는 mock/hardware다. 전용 simulation 모드가 이미 있다고 가정하지 않는다.
- `server/device_tests.py`에는 mock 실행의 simulation 출처 사용이 있다. 실물 EvidenceFiles의 출처 제한과 서로 구분해야 한다.

권장 첫 연결은 기존 mock 흐름의 시뮬 백엔드로 연결하고, Isaac/기준 경로 등 실제 실행 출처를 별도 기록하는 방식이다. 필드명과 검증 규칙은 관제 코드에서 설계한다. 기존 hardware worker에 모의 결과를 실물 관측으로 넣지 않는다.

## 관제 통합 작업 순서

1. 자료의 도로 버전·설정·그래프를 읽어 관제 화면에 같은 좌표로 표시한다. 도로를 화면에서 별도로 다시 작성하지 않는다.
2. 이동 명령 하나의 요청 → 진행 → 결과/실패 → 취소 왕복부터 연결한다. 기존 `execute(command, cancelled)`와 이벤트 계약을 확인하고 기존 테스트를 유지한다.
3. 단일 관제 권한으로 작업대·회차·합류·대기줄의 점유를 관리한다. 도로 간선 이름만 잠그는 것으로 바구니의 겹치는 회전 영역을 해결했다고 처리하지 않는다.
4. 이동 명령 성공, 충분히 정밀하게 정차했다는 관측, 팔 작업 허가, 팔 이탈, 바구니 완전 이탈, 점유 해제를 별도 사건으로 연결한다.
5. 두 대의 인계 경쟁, 앞차 출발과 뒤차 전진, 복귀 차량과 출발 차량의 합류, 오래된 관측, 취소·연결 단절·관제 재시작을 시험한다.
6. 기준 경로 연결이 확인되면 실제 Isaac 바퀴 추종, 지연·제동, 센서 정밀주차, 실물 지도와 배치 좌표 정렬을 별도 검증한다. 그 뒤 실기 전이를 판단한다.

관제 실행에는 로봇/명령/작업/실행 식별자, 도로 버전, 관측 출처, 관측 시각, 수신 단조 시각이 필요하다. 시뮬 시각의 정지·초기화와 관제 Unix 시각을 같은 값으로 취급하지 않는다. 현재 모사의 즉시 정지는 실물 제동 모델이 아니다.

## 인계 파일과 역할

| 파일/모듈 | 사용 목적 |
|---|---|
| `config/layout.json` | 배치·바구니·목표 접합부 치수와 가정 |
| `evidence/routes/route-graph.json` | 도로 v3의 연결·방향·자세 경로 |
| `evidence/routes/routes.json` | 검증한 16개 경로 묶음 |
| `source/pinky_motion/route_paths.py` | 기본 대기·작업대 경로의 생성 정의 |
| `source/pinky_motion/traffic.py` | 단일 프로세스 예약·점유 보존 프로토타입 |
| `source/pinky_motion/fleet_reference.py` | 고정 예제의 미래 경로 시간 조정과 모사 |
| `source/pinky_motion/docking.py` | 관측 유효성 판정 모듈. 영상 검출·후진 제어기는 아님 |
| `evidence/physics/run.json` | 단일 바퀴 구동 녹화 시험의 실제 결과 |

이미지·MP4·HTML은 그대로 복사해 볼 수 있다. USD 장면 재실행은 기존 Isaac 6.1.0-rc.26 환경과 인접 `shopping-robot-digital-twin`의 원본 자산에 의존한다. 소스 자산의 해시는 포함하지만 원본 USD/메시를 재배포하지 않는다.
