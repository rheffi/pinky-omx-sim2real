# 도로 v3: 좌하단 기본 대기와 두 대 운행

2026-10-22. 차로 중심 간격을 35cm에서 24cm로 줄이고, 좌하단 두 대의 기본 대기줄을 연결했다. 기본 대기 → 적재 → 교대 하역 → 기본 대기 복귀의 기준 경로·시간 모사가 통과했다. Isaac 바퀴 추종이나 실기 성공 결과는 아니다.

사용자가 지정한 기존 파일 경로를 유지했다. 폴더 이름은 `route-plan-v2-20261022`지만 HTML·도면·근거 JSON의 내용 버전은 3이다.

## 배치와 동선

- 위쪽 서향 차로 중심은 벽에서 95cm로 유지하고, 아래쪽 동향 차로를 130cm에서 119cm로 옮겼다. 회차 중심 반경은 12cm다.
- 좌하단 대기줄의 Pinky 모델 기준점은 후열 `(0.46, -1.375, 0)`, 선두 `(0.80, -1.375, 0)`이다. 두 대 모두 오른쪽을 향한다. 단위는 m/rad이며 저장된 ROS 지도 좌표가 아니다.
- 바구니 포함 실제 외곽의 합집합 바운딩 박스는 약 61.3×12.7cm, 외곽에 2cm씩 더한 대기줄 영역은 약 65.3×16.7cm다.
- 위쪽 차로에서 왼쪽 바깥 회차로 분기하여 후열로 진입한다. 선두가 비어 있으면 앞으로 이동한다. 출발은 선두에서 완만한 곡선을 따라 아래쪽 본선에 합류한다.
- 선두 출발·후열 전진·복귀는 전체 시간 경로의 외곽을 비교해 조정한다. 로봇별 독립 주차석이 아니라 앞차 우선 대기줄이다. 뒤차가 앞차를 통과하는 이동은 거부한다.
- 현재 예제는 1번이 선두에서 A로, 2번이 후열에서 B로 출발한다. 적재를 마친 뒤에는 A/B 내부에서 인계 순서를 기다린다. 1번은 선두, 2번은 후열로 복귀한다. 임의 주문·복귀 순서에 대한 일반 대기열 배정은 아직 아니다.
- A 출차와 인계 진입의 S곡선을 줄어든 회차에 다시 연결했다. 작업대의 180° 정렬 및 직선 후진 목은 유지하며 작업대별로 한 대씩 허가한다.

## 검사 범위와 결과

[전체 결과](../outputs/routes-v3-001/result.json) · [16개 경로 묶음](../outputs/routes-v3-001/routes.json) · [연결 그래프](../outputs/routes-v3-001/route-graph.json) · [정상 재생 자세](../outputs/routes-v3-001/exchange-frames.json) · [화면 검사](../outputs/replay-check-v3/result.json).

각 로봇의 바구니 포함 보수적 사각 외곽에 2cm를 더했다. 경로 구간의 이동 거리와 회전각으로 모든 모서리의 변위 상한을 구하고, 끝점 사이의 외곽까지 포함하는 영역을 검사한다. 시간 경로는 0.025초 구간으로 검사했다. 이 2cm는 가정한 검사 여유이며 실물의 추종·제동·통신 오차 허용값으로 측정한 수치가 아니다.

| 검사 | 결과 |
|---|---|
| 작업대 간 6개 방향 이동 | 통과 |
| 기본 대기→A/B/인계 3개, 각 작업대→선두/후열 6개, 줄 전진 1개 | 통과 |
| 선두 또는 후열에 정차한 로봇과 본선 전체 회차 | 통과 |
| 선두에 한 대가 있을 때 후열 복귀 | 통과 |
| 후열에 한 대가 있을 때 선두 출발 | 통과 |
| 선두가 점유된 상태에서 후열의 전진 | 차단 |
| 두 대 적재 후 동시 인계 요청 | 1번 허가, 2번 B 내부 대기 |
| 인계 이탈 정보가 오래됨 | 두 대 정지, 1번 점유와 2번 대기 유지 |
| 자동시험 | 36개 통과 |
| 브라우저 | 기본 대기·줄 전진·합류 대기·복귀·정지·시간 탐색·재생 통과, 페이지 오류 없음 |

검사 장애물은 바닥 경계·칸막이와 설정의 가정한 중앙 선반이다. 실측되지 않은 양옆 선반, 고객 바구니, 움직이는 로봇팔 영역은 완전히 모델링되지 않았다. 일부 구간은 2cm 확장 외곽을 제외한 추가 여유가 수 mm 수준이므로 물리 추종 시험이 필요하다.

## 실행 시나리오

속도 0.08m/s 이하, 각속도 0.5rad/s 이하, 적재·하역 각각 3초 사건으로 둔 시간이다. 실제 처리량 측정이 아니다.

| 모사 시간 | 사건 |
|---|---|
| 0초 | 좌하단에서 1번 선두, 2번 후열 대기 |
| 2초 | 1번 A로 출발, 2번은 앞차와 간격을 유지하며 앞으로 이동 |
| 6.25~9초 | 2번 선두에서 합류 대기 |
| 9초 | 2번 B로 출발 |
| 49.4초 | 둘 다 적재 완료 후 인계 요청. 1번 출발, 2번 대기 |
| 92.625초 | 1번 인계 도착 |
| 95.625초 | 1번 하역 완료 후 기본 대기줄로 복귀 |

| 109.9초 | 복귀 경로를 고려한 추가 3.5초 대기 후 2번 인계 출발 |

두 대가 동시에 기준 경로를 진행한 시간은 58.775초다. `stale_exit`에서는 106.4초의 첫 이탈 관측을 오래된 정보로 처리하고 현재 자세에 두 대를 2초간 유지했다. 실제 카메라 관측이나 제동 동작이 아니라 합성 입력에 따른 즉시 정지 모사다.

## 구현과 남은 경계

`route_paths.py`에서 차로와 기본 대기 경로를 정의하고 `routes.py`는 동일한 정의로 연결 그래프를 만든다. 그래프 형식 버전은 2, 도로 내용 버전은 3이며 Nav2 Route Server 배포 파일이 아니다. `fleet_reference.py`는 기존 예약 모듈과 전체 미래 경로의 외곽 검사를 함께 사용한다. 간선별 예약 이름만으로 교차 외곽 충돌이 해결되는 것은 아니다.

재생은 계산된 자세를 표시하며 실제 바퀴 제어·센서 정밀 도킹·관제 주문/상품 처리·OMX/ACT 실행은 연결되지 않았다. 실제 운행에서는 단일 관제 권한, 관측 기반 경로 진입/이탈, 추종/제동 오차, 지연과 중단 후 재개를 검증해야 한다. 바구니 바닥 저항 제외 가정은 유지한다.

이전 v2 출력은 `outputs/routes-v2-002`에, 수정 직전 화면·도면은 [보존 폴더](../outputs/replay-v2-before-v3/replay.html)에 남겼다. 기존 관제 저장소와 USD 원본은 수정하지 않았다.
